# 01 · 网络层：出口可信度与泄漏面

> 核心问题：**平台看到的「你从哪里来」是否可信、是否唯一、是否稳定？**

---

## 1. 网络层的三个目标

1. **可信的出口**：出口 IP 属于普通消费者网络，而不是被大量滥用的机房段。
2. **零泄漏**：除了指定出口，不存在任何能暴露真实网络的旁路。
3. **稳定且自洽**：出口长期固定，且与时区、语言、支付地区等其他信号互相吻合。

---

## 2. 出口质量的评估维度

| 维度 | 关注点 | 方向 |
| :--- | :--- | :--- |
| **IP 类型** | 住宅 / 移动 / 企业 / 机房（Hosting） | 优先住宅或移动网络；机房 IP 默认高风险 |
| **ASN 信誉** | 所属运营商是否为主流消费级 ISP | 大型本地运营商 > 小众 VPS 商 |
| **共享程度** | 同一 IP 上同时有多少用户 / 账号 | 独享 > 小范围共享 > 公共机场 |
| **历史污染** | 是否在代理/VPN/欺诈数据库中有记录 | 选择前和使用中都要定期查 |
| **地区政策** | 该地区是否在服务支持范围内 | 必须是官方支持地区 |
| **地理一致性** | 与本机时区、语言、支付地区是否吻合 | 尽量减少需要「伪装」的维度 |
| **延迟特征** | RTT 是否与声称的地理位置相符 | 近距离地区天然更容易自洽 |
| **稳定性** | 是否频繁换 IP / 换城市 / 换国家 | 固定出口，变化要少而慢 |

> **地区选择的思路**：不是「哪个国家最好」，而是「哪个支持地区能让我需要伪装的维度最少」。例如与本地同时区的支持地区，能天然消除时区与作息冲突。

---

## 3. 泄漏面清单（必须逐项封堵）

| 泄漏面 | 机制 | 封堵方向 |
| :--- | :--- | :--- |
| **IPv6 旁路** | 双栈网络下 AAAA 解析成功后可能绕过只代理 IPv4 的隧道直连 | 在代理核心对目标域名屏蔽 AAAA / 丢弃 IPv6 流量，或全局接管 IPv6 |
| **DNS 泄漏** | 目标域名的 DNS 查询走了本地运营商 | DNS 也走代理或加密 DNS，并与出口地区一致 |
| **分流规则遗漏** | 平台依赖的子域、CDN、验证码、遥测域名没走代理 | 维护完整的域名清单，不只是主域名 |
| **WebRTC** | STUN 请求暴露本地/真实公网 IP | 浏览器策略 + 网络层双重处理 |
| **应用直连** | 桌面/移动客户端不遵守系统代理 | 使用 TUN 级全局接管，而非仅系统代理 |
| **切换瞬间** | 节点切换、断线重连时短暂直连 | 启用「断线即断网」类机制，避免在切换时访问 |

---

## 4. 工程原则

- **在最底层解决**：能在网络层/代理核心解决的，不放到浏览器插件里解决。
- **精准而非粗暴**：例如不要为了防 IPv6 泄漏直接关闭系统 IPv6，应只针对目标域名处理，避免影响日常使用。
- **配置即代码**：代理规则用模板 + 脚本管理，可备份、可回滚、可校验（见 `tools/`）。
- **定期复测**：节点质量会变化，ISP 会被重新标记；把检测纳入日常流程。

---

## 5. 验证方法

- 出口 IP 类型 / ASN / 风险评分：多个独立数据源交叉核对，不依赖单一检测站。
- 目标域名的 A / AAAA 解析结果：确认 AAAA 被屏蔽或走代理。
- WebRTC 泄漏测试：确认无真实地址候选。
- 时区 / 语言 / IP 地区一致性：浏览器侧与网络侧对照。

> 对检测站结果要有判断力：它们的规则是简化的，可能存在误报或漏报。
