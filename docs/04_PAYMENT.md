# 04 · 支付层：付款信号与账号画像的一致性

> 核心问题：**付款这件事，是否和账号的其他信号讲的是同一个故事？**
> 付费是封号的高发节点：它引入了一整套独立的金融风控，并且会把真实身份信息带进来。

---

## 1. 支付环节暴露的信号

| 信号 | 说明 |
| :--- | :--- |
| **发卡地区（BIN 国家）** | 卡由哪个国家的哪家机构发行 |
| **卡类型** | 借记/信用/预付/虚拟卡；部分虚拟卡号段被广泛标记 |
| **账单地址验证** | 账单地址与发卡行记录、与 IP 地区是否一致 |
| **支付处理方风控** | 支付处理方自身的欺诈评分、拒付历史、跨商户数据 |
| **支付渠道** | 网页直付 / 应用商店内购 / 企业与 API 计费等，不同渠道暴露给平台的信息不同 |
| **失败与重试** | 多次失败、换卡重试本身就是强风险信号 |

---

## 2. 方向性原则

1. **一致性**：支付地区应与出口地区、账号画像相容；跨度越大越可疑。
2. **减少暴露面**：优先选择让平台接触到的金融信息更少、更「干净」的渠道（例如由中间平台结算、平台只拿到收据的渠道）。
3. **不要反复试错**：支付失败后不要短时间内换多张卡反复尝试；先排查原因。
4. **一卡一号**：同一支付方式绑定多个账号会形成强关联边。
5. **提前规划续费**：订阅是持续行为，所选渠道要能长期稳定续费，而不只是「首次能付成功」。

---

## 3. 渠道比较框架

评估任何支付渠道时，用同一套维度打分：

| 维度 | 问题 |
| :--- | :--- |
| 信息暴露 | 平台能看到卡号/发卡行/账单地址吗？ |
| 地区一致 | 渠道所属地区与账号地区是否一致？ |
| 稳定续费 | 能否长期自动续费，不需要频繁人工干预？ |
| 失败代价 | 失败时是只拒付，还是会连带账号风险？ |
| 获取成本 | 获取该渠道所需的资源、合规成本 |

> 具体渠道（哪种卡、哪个商店、哪个地区）属于会随时间变化的「方案」，记录在 playbooks 与 research 中，不写死在这里。

---

## 4. 待持续研究的方向

- 不同渠道在当前时间点的实际可用性与风险。
- 支付失败与封号之间的时间关系（即时 vs 延迟复核）。
- 套餐升级/降级、退款对账号风险的影响。
