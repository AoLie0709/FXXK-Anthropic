# 03 · 身份层：账号来源与关联图谱

> 核心问题：**这个账号是谁？它从哪里来？它和哪些别的身份连在一起？**

---

## 1. 身份信号的构成

| 信号 | 平台关心什么 |
| :--- | :--- |
| **登录方式** | 邮箱密码 / 第三方 SSO（Google、Apple 等）——SSO 会继承身份提供方的信任与历史 |
| **邮箱来源** | 主流个人邮箱 vs 批量注册泛滥的服务 vs 临时邮箱 vs 带有特定地区特征的域名 |
| **手机号** | 实体运营商号码 vs 虚拟/VOIP 号码；号码归属地；是否被大量账号复用 |
| **账号年龄与历史** | 身份提供方账号是否有正常使用历史，而不是「刚注册就用」 |
| **注册环境** | 注册瞬间的网络、设备、浏览器信号（第一印象极重要） |

---

## 2. 方向性原则

1. **身份来源要「自然」**：优先主流、个人用途、有正常历史的身份；避开批量注册重灾区和带明显不一致地区特征的身份。
2. **SSO 是双刃剑**：它带来身份提供方的信任，也把身份提供方账号上的所有历史（绑定信息、关联账号、风险记录）一并带过来。用于 SSO 的上游账号必须同样干净、专用。
3. **专号专用**：用于 Claude 的身份不与个人主力身份、其他服务账号混用。
4. **注册环境 = 使用环境**：注册时就要在最终的网络与浏览器环境下进行，不要「先随便注册，后面再整」。
5. **避免可连坐的共享点**：同一手机号、同一辅助邮箱、同一支付卡、同一设备，都会成为关联边。
6. **冷启动要温和**：新账号初期避免高强度、异常模式的使用。

---

## 3. 关联图谱思维

复盘与设计时，把每个账号想成图中的节点，问自己：

```
          [邮箱/SSO 上游账号]
                 │
[设备/浏览器] ── 账号 ── [出口 IP]
                 │
          [手机号] [支付方式]
```

- 每一条边是否只连向这一个账号？
- 任何一个相邻节点，是否曾经连接过被封账号？
- 如果其中一个账号出事，会不会顺着边波及其他账号？

---

## 4. 待持续研究的方向

- 不同邮箱/SSO 来源在实际中的风控差异（需要实测数据，而非经验传言）。
- 手机号验证的触发条件与可接受号码类型的变化。
- 账号「养成期」的合理时长与使用强度。
