## 💡 核心认知：被封了 6 个号后，我悟出的三条大白话铁律

### 1. 强烈建议保持全部信息一致！这是最核心、也是普通用户最难做到的点

为什么大家都说防封难？**因为 Anthropic 的风控不是只看一个 IP，而是跨平台、跨服务商打通的全链路数据交叉比对。**  
只要其中有一个环节对不上，权重分直接爆炸！特别是以下几个极度恶心的“致命撕裂点”：

- **Stripe 收款风控与 A÷ 强同步**：  
  很多人以为买个海外代理就完事了，殊不知 **Stripe 的支付风控雷达信息是直接跟 Anthropic 组织后台同步的！**  
  你的**信用卡发卡行区域**、**结账填写的账单地址**、**当前发起的代理 IP**、以及**账号注册时的画像信息**——如果这四个东西不一致（比如拿着香港/国内虚拟卡，账单写免税州，IP 在洛杉矶，账号又是另一个画像），风控权重直接拉满暴扣，付完款当天或者第二天秒封！
- **弹了 Persona KYC 认证？画像不一致直接暴毙**：  
  如果你的操作触发了 A÷ 的风控阈值，要求你做真人 KYC 认证（调取摄像头扫脸、传护照）。你提交的真人身份与证件归属地，如果跟 A÷ 系统先前根据你的行为轨迹、访问节点推断出来的用户画像不一致，也会导致封号权重直线上升甚至当场落锁封号。
- **底层网络三大漏勺：IPv6、DNS、WebRTC 穿透**：  
  - **国内公网 IPv6 穿透**：国内电信、联通、移动现在普遍默认分配公网 IPv6。很多电脑/手机代理软件只接管了 IPv4，IPv6 直接直连 Cloudflare！人家服务器一眼就看到你的真实省市运营商；
  - **本地 DNS 泄露**：虽然你走的海外代理，但浏览器的 DNS 域名解析请求却顺着本地系统跑去了 114.114.114.114 或国内运营商 DNS，直接露馅；
  - **WebRTC 局域网与公网穿透**：浏览器内置的 WebRTC 协议为了建立音视频通道，会在后台通过 STUN 协议默默把你本机的真实局域网 IP 和国内公网 IP 暴露出来，网页端 JS 脚本一读一个准。  
  
👉 **为什么这对于普通用户来说非常困难？**  
因为普通人根本不可能天天去检查什么 TUN 虚拟网卡、WebRTC 策略、DNS 转发规则和信用卡 BIN 码。只要漏了一个细节，前面的努力全白费！

### 2. 积分扣分制：封号从来不是因为单点，而是“弱信号累加”

千万别以为“我做错了某一步就会立刻封号”。Anthropic 联合 Cloudflare、Stripe 和 Persona 建立的是一套**动态风险积分模型（类似驾照扣分制）**：
- **单个轻微异常不致死**：比如偶尔网络抖动跳了节点、窗口尺寸稍微罕见，系统可能只记 5~10 分风险，账号依然能正常用；
- **跨维度冲突直接暴毙**：如果你代理走美西（+0分），但 Mac 电脑名称叫“张三的MacBook”（+20分），国内 DNS 泄露（+25分），浏览器里装了指纹伪造插件被识破（+25分），输入框每次都是瞬间大段粘贴（+15分） $\rightarrow$ **总分瞬间突破警戒线，触发封禁机制！**
- **恶心的“延迟秋后算账”**：很多人误以为“我改了个配置，今天能聊，说明我成功了”。**错！** 风控往往会把封号推迟到**首次账单付款复核**、**后台异步大模型安全审计**或**周末凌晨**统一批量收割，让你根本不知道自己到底死在哪一步。

### 3. 为什么写防御探针去对抗，反而死得更快？

被封之后，很多人第一反应就是找各种“防指纹插件”、“随机加 Canvas 噪点”、“篡改 User-Agent”。**这完全是反向操作！**
- **“自首式”上报**：A÷ 的前端脚本在后台做了大量自洽性检查。比如你用插件把 UA 伪装成 Windows，但你的底层 Chromium 接口依然如实汇报你是 Apple Silicon 芯片。脚本一比对，直接在后台给服务器发送：`ua_client_hints: "mismatch"`。**你装的插件等于主动举手自首！**
- **空白子网页（Iframe 夺舍）**：Cloudflare 脚本会在后台毫秒级生成一个 `about:blank` 隐藏子网页，在任何浏览器插件根本来不及注入的瞬间，直接提取子网页里纯净原生的语言和物理内存。主页面伪装得再花哨，子网页依然瞬间把真实的简体中文和 16GB 物理内存暴露得一览无余！
- **保持环境一致性比防御更重要**：在现代探针面前，伪造的破绽远多于原生环境。**保持系统、网络、账号全链路信息自洽，不搞多余动作，才是存活率相对最高的方式。**

## 🛠️ 怎么防封？拿真金白银换来的最接地气实操指南

> **再次强调**：**目前防封纯属实验阶段，成功概率依然很低！**  
> 以下操作不是什么“免死金牌”，而是作者为了消除上面那些恶心探针，在 **2026 年 10 月 20 日** 开辟的新一轮实测配置：

### 1. 电脑名字脱敏（防桌面端 D-01 探针）
在 Mac 终端里运行下面这行命令，把中文名字改成普通的英文名，别出现中文拼音：
```bash
sudo scutil --set ComputerName "macbook-air"
sudo scutil --set HostName "macbook-air"
sudo scutil --set LocalHostName "macbook-air"
```

### 2. 彻底关掉无线网 IPv6（防手机和电脑 IPv6 穿透 M-03 探针）
国内运营商的公网 IPv6 是最大元凶，运行以下命令彻底关闭 Wi-Fi 的 IPv6：
```bash
sudo networksetup -setv6off "Wi-Fi"
```

### 3. Chrome 保持 0 插件，建一个干净的独立 Profile（防 W-01、W-06 探针）
- 不要在平时刷网页、装了一堆国内插件的日常浏览器里登 Claude；
- 点击 Chrome 头像 $\rightarrow$ **添加新个人资料（Profile）** $\rightarrow$ **不要装任何防指纹插件、不要装脚本**；
- 原生干净的 Chrome 在风控眼里反而是信誉最高的。

### 4. 桌面端用官方允许的方式关闭遥测（防 D-05 探针）
**不要用第三方黑产工具去 Hook 客户端！** 直接打开官方支持的配置文件：  
`~/Library/Application Support/Claude/claude_desktop_config.json`  
写入以下内容，官方合规关闭后台数据采集：
```json
{
  "disableNonessentialTelemetry": true,
  "disableEssentialTelemetry": true,
  "disableNonessentialServices": true,
  "disableAutoUpdates": true,
  "modelCatalogEnabled": false,
  "skipWebFetchPreflight": true
}
```

### 5. 换号重生：最省事的办法是新建一个 Mac 系统用户
如果你的号已经被封过，单清 Cookie 根本逃不脱 `ant-did`、Keychain 和 Secure Enclave 硬件芯片的图谱连坐。  
**最干净彻底的物理隔离法**：
1. 打开 Mac【系统设置】 $\rightarrow$ 【用户与群组】 $\rightarrow$ **新建一个标准用户（例如起名叫 Work）**；
2. 登录进这个全新系统用户，系统会自动生成完全隔离的 Keychain、全新的安全芯片上下文和全新的 Chrome 配置；
3. **旧的充值过被封账号的 Apple ID 绝对不要再给新号充值**（`original_transaction_id` 已经进黑名单），新号必须使用全新美区 Apple ID + 官网礼品卡充值。
